# Operating Rhythm

Founder-Led Sales Call OS works best as a weekly GTM learning loop.

## Monday

- Review last week's `weekly_sales_learning_memo.md`.
- Pick the top narrative experiment for the week.
- Update discovery questions before new calls.
- Confirm founder follow-ups from `deal_rescue_queue.csv`.

## Tuesday

- Run sales calls.
- Capture notes using the sales call note template.
- Mark objections and unclear next steps while the call is fresh.

## Wednesday

- Review active deals.
- Rescue any high-fit deal with pain but no clear next step.
- Add proof points requested by prospects.

## Thursday

- Compare new calls against repeated objections.
- Update the deck, homepage, or demo talk track if prospects are confused.
- Confirm which segments are showing real urgency.

## Friday

- Export call notes.
- Run `make run`.
- Review the objection bank and deal rescue queue.
- Read the weekly memo before the GTM review.
- Decide what to test next week.

## How to use outputs in founder meetings

Use `outputs/weekly_sales_learning_memo.md` as the meeting agenda.

Use `outputs/deal_rescue_queue.csv` to assign founder follow-ups.

Use `outputs/objection_bank.csv` to decide which proof points to create.

Use `outputs/narrative_experiments.md` to pick next week's messaging test.

## Meeting questions

- Which objection repeated the most?
- Which deals can still be rescued?
- Which prospects were weak fit and should not consume founder time?
- Which part of the pitch is unclear?
- Which proof point should be created first?
- What should change in the next five sales calls?
